评审结论：现有架构具备两个可利用的测试条件——回调模拟器和可配置的隔离主题；但它们不足以证明支付异常路径可控、端到端隔离可靠或结果可重复。当前只能形成**待验证的改进方案**，不能认定架构可测试性已经通过。

**1. 任务理解与范围**

目标是评估“订单服务 → 消息队列 → 支付适配器 → 外部支付商”链路，形成能够验证异步处理、资金状态和故障恢复的执行方案。

成功标准应是：另一位工程师能够按固定配置准备环境、触发场景、观察结果并保存证据。此次仅做文本评审，读取了本地 Skill 规范，未运行系统测试、访问外部服务或执行生产写操作。

**2. 输入审计**

| 类型 | 内容及判断边界 |

**3. 风险与优先级**

| 优先级 | 风险与依据 | 处理顺序 |
|---|---|---|
| P1 | 外部支付成功、本地响应丢失后重试，可能造成重复资金动作或长期状态不一致。影响高，发生概率未知。 | 优先核验幂等和未知结果处理契约，再测试。 |
| P1 | 消息重复、消费崩溃、回调乱序可能造成重复处理、丢失处理或状态回退。F1、F2提供了相关边界，但保护机制未知。 | 核验确认时机、状态转换和去重范围。 |
| P1 | 隔离主题可能只隔离消息，无法防止共享数据、回调或外部账号污染。依据 F4。 | 故障实验前验证完整隔离。 |

**4. 核心分析与执行项**

应先确认以下边界：订单状态写入与消息发布是否一致；适配器调用支付商与消息确认如何排序；回调由谁接收、如何关联订单、在哪里持久化。除消息队列边界外，其他异步边界仍需架构制品确认。

“可用”表示输入声明存在能力；“待核验”表示没有证据；“缺失”仅用于明确不存在的入口，不折算为未经依据的数字评分。

| 维度／接缝 | 当前判断 | 建议、价值及成本 |
|---|---|---|
| 订单与队列边界 | 待核验事务和确认语义 | 明确发布、消费、确认、重试和持久化的先后关系；使用真实隔离队列测试投递行为。价值是定位丢失或重复窗口。成本：中，涉及契约梳理，是否修改实现取决于证据。 |
| 适配器与支付商边界 | 依赖已知，替换能力待核验 | 将外部调用放在明确接口后，通过测试部署配置选择协议替身；支持固定响应、超时、断连及“已记账但响应丢失”。价值是控制资金风险路径。成本：中，需维护契约和替身账本。 |
| 回调边界 | 模拟器可用，覆盖范围待核验 | 扩展或配置模拟器支持重复、乱序、延迟、错误关联和无效签名；保留真实接收与校验链路。价值是验证异步状态转换。成本：低至中，取决于现有能力。 |
| 隔离与数据准备 | 仅主题隔离已知 | 每次运行分配独立主题、消费组、测试数据范围和回调路由；核验账号、凭据、缓存及共享资源。准备有效、重复和未知订单等脱敏数据。价值是降低污染和并发干扰。成本：中，共享资源完全隔离可能更高。 |
| 可控制性与故障注入 | 显式入口缺失 | 在测试部署使用替身、网络代理及进程终止控制；支持精确暂停在外部结果落地、消息确认等边界。价值是稳定触发崩溃窗口。成本：中至高，精确暂停通常需要代码接缝。 |
| 确定性 | 待核验 | 为业务重试和计时提供可替换时钟、固定随机种子；真实队列使用有截止时间的条件等待，避免固定睡眠。价值是降低偶发失败。成本：中；无法保证真实分布式调度完全确定。 |
| 可观察性 | 待核验 | 关联运行、订单、消息、支付尝试和回调；记录状态转换、确认、重试及外部结果，按需提供只读状态查询。价值是区分故障位置。成本：中，并有存储与脱敏成本。 |
| 环境复现与自动化接口 | 待核验 | 保存组件版本、配置摘要、队列策略、契约版本、种子、替身脚本和运行步骤；自动化准备、刺激、等待、断言、取证和清理。价值是让失败可重放。成本：低至中，需持续维护。 |

上述都是建议能力，未确认系统已有相关字段或接口。故障控制应限制在测试部署或进程内，带访问控制和自动恢复；不增加生产可调用的任意改状态、跳过鉴权入口。

替身采用分层策略：

- 业务单元测试使用轻量替身验证分支和状态转换，不能证明队列投递行为。
- 集成测试使用真实隔离队列、真实持久化组件和支付协议替身。
- 沙箱契约测试核验真实协议、认证、签名及回调格式。替身通过不能证明支付商真实行为一致。
- 端到端测试复用回调模拟器，但必须确认其覆盖能力；不能将模拟器等同于支付商回调。

以下为最小验证集。所有场景均须保存运行配置、输入、时间线、断言及原始证据；清理只作用于该次运行资源。

| 场景 | 前置条件与刺激 | 拟定断言及所需证据 |
|---|---|---|
| V1 正常链路 | 隔离环境、契约和状态机已确认；发布有效支付消息并发送有效回调。 | 在预先批准的期限内达到约定终态；订单、消息、外部尝试和回调可关联。保存状态记录、替身账本和确认记录。 |
| V2 重复投递 | 具备固定业务身份和重复投递能力；重复发送同一业务请求，再分别发送同消息身份和新消息身份。 | 按批准的幂等范围处理，不产生额外资金动作；保存实际投递、消费、外部调用及账本记录。不能仅凭最终订单状态判断。 |
| V3 外部成功但响应丢失 | 替身先记录成功，再使响应超时；触发系统既定重试或恢复。 | 按约定进入查询、等待、重试或人工处理流程，并避免重复资金动作；保存首次成功、后续请求、幂等键和状态时间线。具体恢复策略须先决定。 |
| V4 消费崩溃 | 可在“外部成功后、消息确认前”暂停；终止适配器再重启。 | 验证重投及恢复符合契约，不丢失业务结果、不重复资金动作；保存崩溃位置、确认记录、重投记录和账本。 |
| V5 回调异常 | 模拟器能够构造重复、乱序、延迟、未知订单及无效签名回调；分别执行。 | 重复回调不重复生效，状态不发生禁止的回退，未知关联不修改其他订单，无效签名不被接受；保存校验结果与前后状态。 |
| V6 隔离验证 | 两套运行资源，并发使用相同业务标识；分别发布消息和回调。 | 消费、状态、回调和外部账本均不串扰。核验消费组、路由、数据及账号隔离，而非只比较主题名。 |
| V7 超时与复现 | 重试上限和超时语义已批准；注入持续超时，随后恢复。使用同一制品、配置和种子重复运行。 | 重试有界，截止后进入约定状态，恢复后按规则处理；重放得到一致业务结论。保存尝试次数、时钟控制、配置摘要及每次结果。 |

这些是**待执行的断言**。执行者应先做正常基线，再引入单一故障，最后组合故障；不能从一次通过推广到全部场景有效。

**5. 阻塞条件与残余风险**

以下条件阻塞相应验证结论：

- 未明确状态机、幂等范围和未知支付结果策略：无法判断 V2—V5 的正确结果。
- 未证明数据、回调和外部账号隔离：停止故障实验。
- 无法证明故障确实发生在指定位置：只能记录实验未覆盖目标窗口，不能记为通过。
- 缺少完整关联记录或外部账本证据：无法证明不存在重复资金动作。

若出现跨环境污染、非测试凭据使用或未预期资金动作，应停止发送刺激、撤销本次故障配置并人工核对；不能把数据库回滚当作外部支付撤销。

残余风险包括支付商真实行为与替身偏差、沙箱与实际环境差异、长延迟回调及真实并发调度。它们需要额外契约证据或后续验证；是否接受及接受期限由业务、支付和发布负责人决定。

**6. 下一步与人类决策**

建议按以下顺序执行：

1. **订单与支付负责人**补齐架构图、状态机、消息确认策略、支付商幂等及回调契约。
2. **平台与测试负责人**建立隔离清单，核验模拟器能力，执行 V1、V6，先证明正常链路和隔离。
3. **适配器负责人**增加最小支付替身及故障控制能力，执行 V2—V5、V7。
4. **测试负责人**提交证据包：版本配置、步骤、刺激、实际结果、断言、原始记录和未覆盖项；由相关负责人评审。

需要人类明确决定：未知支付结果如何处理、幂等键及有效期、允许的状态转换、重试与超时边界、人工接管条件，以及隔离和故障接缝的投入预算。
