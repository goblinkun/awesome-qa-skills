以下为**功能测试初版，尚未执行任何测试**。面向 30 分钟发布验证，优先覆盖交易主链路、重复支付回调和越权风险。接口及状态规则缺失的用例标为条件可执行，不能据此宣称验证通过。

**1. 任务理解**

范围：登录 → 购物车 → 下单 → 支付，以及这些环节之间的身份、价格、库存、订单和支付结果传递。

| 类型 | 内容 |
|---|---|
| 已确认事实 | 验证窗口只有 30 分钟；支付回调可能重复到达；接口字段、角色权限矩阵和支付最终状态规则尚未提供。 |
| 当前假设 | 有隔离测试环境、测试买家 A/B、可控商品及库存；支付使用沙箱或模拟能力；能够查询订单、支付及相关业务记录。以上均需确认。 |
| 建议验收基线，待确认 | 同一支付事实重复通知不应重复产生财务或履约副作用；订单金额应可追溯到确认时的价格规则；用户不能访问或操作未获授权的他人交易。 |
| 暂不纳入本轮 | 全量角色覆盖、多浏览器与设备组合、性能压测、完整优惠组合、完整退款和对账流程。若本次发布涉及这些变更，应重新排序。 |

用例中的“订单标识、支付标识、事件标识”均为业务概念，**不是已知接口字段名**。失败、取消、处理中、成功也只是场景描述，需映射到真实状态及允许的转换。

**2. 风险和优先级**

| 优先级 | 风险 | 30 分钟内的取舍 |
|---|---|---|
| P0 | 主链路不可用、金额不一致、交易归属错误 | 必须先验证一笔可追踪的完整交易。 |
| P0 | 重复回调导致重复记账、扣库存、发货或发放权益 | 优先验证相同事件连续重复及并发重复；只看页面不足以证明幂等。 |
| P0 | 支付结果丢失、乱序通知破坏最终状态、付款后重试产生额外交易 | 依赖最终状态规则；未补齐时记为阻塞。 |
| P0 | 重复提交生成非预期订单或支付；越权；超卖 | 选择最小代表场景验证，不能替代全量覆盖。 |
| P1 | 登录失败提示、数量边界、商品失效、优惠及购物车持久化异常 | P0 完成后按变更范围选择；时间不足保留为未验证。 |

P0 指可能阻断购买、损害资金/库存一致性或暴露交易数据的风险。具体发布阻断标准仍需发布负责人确认。

**3. 核心功能覆盖**

| 环节 | 正常覆盖 | 异常、边界和集成关注 |
|---|---|---|
| 登录 | 有效账号登录，身份正确 | 错误凭据、会话失效；会话与交易归属 |
| 购物车 | 添加、修改、删除，金额更新 | 数量边界、库存不足、商品下架、价格变化；购物车与商品服务 |
| 下单 | 确认商品、金额、地址，生成订单 | 重复提交、库存竞争、越权；订单与库存服务 |
| 支付 | 发起支付，查询交易结果 | 取消、失败、超时、重复/并发/乱序回调；支付与订单、记账、履约服务 |
| 权限 | 用户操作自己的交易 | 未登录、用户 B 操作 A 的交易；其他角色待矩阵补齐 |

**4. 关键场景清单**

统一证据要求：记录环境版本、用例编号、时间、测试账号、商品、数量、金额及可用的业务关联标识。截图证明界面表现；响应、日志或业务记录证明服务端结果。证据需脱敏。

所有用例当前状态均为**未执行**。“待确认”项未补齐时，应记录为**阻塞**，不能填写通过。

|---|---|---|---|---|
| **T01 P0 正常主链路** | 有效买家 A、有效地址、库存充足商品、沙箱支付；金额及成功状态规则明确 | 登录；添加商品；改为 2 件再改回 1 件；下单；支付；刷新订单 | 身份及订单归属正确；数量和金额按确认规则一致；订单、支付及已配置的业务副作用一致；最终状态待规则补齐后判断 | 登录与结算截图、订单和支付记录、关联日志、金额计算依据 |

| **T06 P0 状态冲突/乱序边界** | 有合法且可模拟的冲突事件；明确状态转换、事件顺序依据及观察期限 | 按规则允许的测试组合发送新旧事件，例如先收到成功结果再收到旧失败通知 | 最终结果严格符合状态规则；不能自行认定“成功永远优先”或“最后到达者优先” | 事件发生与到达时间、状态历史、支付查询结果、规则依据；缺规则则阻塞 |
| **T07 P0 交易越权** | A 的测试购物车/订单；买家 B 和未登录会话；明确买家资源访问规则 | B 和未登录会话分别尝试读取、修改 A 的购物车/订单及发起支付 | 未授权操作被拒绝，无敏感信息泄露，无业务变化；具体状态码待接口约定 | 脱敏请求/响应、授权日志、操作前后业务记录 |

**5. 执行备注**

建议单人、数据和工具预先准备好的时间分配：

| 时间 | 执行内容 |
|---|---|
| 0–3 分钟 | 确认隔离环境、版本、规则、测试数据、回调重放和证据查询能力；标出阻塞项 |
| 3–9 分钟 | T01，保留完整交易证据 |
| 9–16 分钟 | T02、T03，重点核对实际副作用 |
| 16–21 分钟 | T04、T05；T06 仅在规则和事件已准备好时执行 |
| 21–25 分钟 | T07、T08 的代表场景 |
| 25–30 分钟 | 核对证据、登记结果及发布风险；有余量再选与本次变更直接相关的 P1 |

这是一份时间预算，不能保证全部完成。工具、规则或数据准备耗时应计入窗口；不足时保留未执行项，不能压缩观察期后宣称一致性成立。

**停止条件与发布判断：**

- 环境指向生产、可能发生真实扣款，或隔离/恢复条件不成立：停止相关操作。
- 出现重复资金或履约副作用、越权、金额错误、超卖、主链路阻断：停止放行，保留证据并排查；其他独立用例可继续。
- 缺最终状态规则、无法生成有效回调、无法观察副作用：相关 P0 标记阻塞；不能认定支付验证通过。
- 异步处理超过约定期限仍不一致：按规则判失败；未提供期限时记为无法判定。
- 30 分钟到时停止新增场景，汇总通过、失败、阻塞、未执行项。发现缺陷并修复后，必须重新验证缺陷及受影响的 P0。

**仍可能未验证的风险：**长期重试、跨进程幂等、不同事件标识表达同一支付事实、支付侧重复扣款、完整角色权限、退款/取消交叉状态、长期对账、优惠组合及并发容量。重复相同回调通过，不能代表这些风险都已排除。

**6. 待确认问题**

执行前优先补齐：

1. **接口契约**：登录、购物车、订单、支付及回调的字段、错误码、关联方式、验签方式；重复事件与重复业务事实如何识别。
2. **权限矩阵**：买家、访客及其他角色可读取和操作哪些资源；共享购物车或代付是否存在。
3. **支付状态规则**：最终状态、合法转换、冲突处理依据、重试行为、查询兜底及一致性期限。
4. **业务规则**：价格锁定、优惠与舍入、库存占用/释放时点、重复提交的产品预期。
5. **执行条件**：测试环境、账号及数据、沙箱能力、回调模拟工具、记录查询权限和本次发布变更范围。
