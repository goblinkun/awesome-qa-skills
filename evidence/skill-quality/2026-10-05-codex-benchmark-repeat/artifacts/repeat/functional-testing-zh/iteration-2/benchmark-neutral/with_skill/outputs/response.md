**1. 任务理解**

这是可供评审和执行的功能测试初版，**尚未执行任何测试**。范围为登录 → 购物车 → 下单 → 支付，重点验证资金、订单、身份和库存的一致性。

**已确认事实**

- 发布验证窗口只有 30 分钟。
- 支付回调可能重复到达；这不等于已经发现重复处理缺陷。
- 接口字段、角色权限矩阵、支付最终状态规则尚未提供。

**当前假设，执行前需确认**

- 使用隔离测试环境及支付沙箱，不发生真实扣款。
- 有两个普通测试账号 A/B、可售商品、可控库存，以及订单、支付和业务日志的只读查询能力。
- 可以通过获授权的测试入口重放、并发投递支付回调。
- 暂以“同一支付交易的业务效果只生效一次”“交易身份和金额必须匹配”“账号不能访问其他账号的私有交易”为候选验收规则。它们需要业务或接口负责人确认。
- 文中“订单标识、交易标识、金额”等是业务概念，**不是已知接口字段名**；不预设具体状态枚举、错误码和响应时限。

**2. 风险和优先级**

| 优先级 | 风险 | 本次取舍 |
|---|---|---|
| P0 | 重复回调导致重复记账、库存变更、履约或权益发放 | 优先验证顺序重复和并发重复；不能仅检查页面或返回码 |
| P0 | 支付金额、交易或订单错误关联，伪造通知被接受 | 验证身份、金额及通知可信性；接口契约缺失时标记阻塞 |
| P0 | 登录绕过、跨账号访问订单或支付信息 | 验证普通用户之间的隔离；完整角色矩阵另行补齐 |
| P0 | 支付成功但订单未收敛，或重复提交引发重复扣款 | 验证主链路及重复提交；最终状态规则缺失时不能判定通过 |
| P0 | 服务端接受错误价格、超卖或库存重复扣减 | 主链路核对金额和库存；专项边界无法完成时保留为未验证 P0 |
| P1 | 购物车数量校验、登录错误提示、会话到期恢复异常 | 选代表性场景，其余进入下一轮 |
| P1 | 取消、失败、超时后的展示或恢复异常 | 覆盖设计保留；涉及资金错账时升级为 P0 |

30 分钟优先覆盖高风险主链路和重复支付通知，暂不展开完整浏览器矩阵、优惠组合、所有支付渠道及长时间补偿流程。**时间不足不降低风险等级；未验证 P0 不能因冒烟通过而视为已排除。**

**3. 核心功能覆盖**

| 流程 | 关键覆盖 | 集成及判断来源 |
|---|---|---|
| 登录 | 正常登录、错误凭证、会话失效、身份隔离 | 身份服务、会话机制、权限规则 |
| 购物车 | 添加、更新、删除、数量边界、金额计算 | 商品价格、库存、账号归属 |
| 下单 | 金额核对、重复提交、价格及库存变化 | 订单服务、库存服务、运费/优惠规则 |
| 支付 | 正常完成、重复通知、非法通知、延迟及乱序 | 支付沙箱、通知处理、订单更新、记账及履约 |

退款、售后、结算及性能压测不纳入本轮。若支付成功直接触发履约或权益发放，其重复触发检查仍在范围内。

**4. 关键场景清单**

所有用例默认继承上述测试环境假设。证据统一保存执行时间、版本、账号代号、订单/交易关联标识和操作前后快照；敏感凭证及完整支付信息应脱敏。

“待确认”表示缺少验收规则；“阻塞”表示缺少执行条件。两者均不能记为通过。

| ID / 优先级 / 类型 | 前置条件 | 操作 | 预期判断 | 证据 |
|---|---|---|---|---|
| T01 / P0 / 正常全链路 | A 可登录；商品有库存；价格、运费等计算规则可查；沙箱支持成功支付 | 登录；添加商品；改数量并删除一个商品；结算；提交一次订单；支付一次；查询关联记录 | 各页面商品与数量一致；金额按确认规则计算；订单与交易正确关联；支付及订单按确认规则收敛；相关业务效果符合数量要求。最终状态规则缺失时，支付段待确认 | 登录及购物车截图、金额明细、订单/交易记录、回调及处理日志、库存与业务效果前后快照 |
| T02 / P0 / 异常登录 | 一组错误凭证；可使 A 会话失效 | 用错误凭证登录；随后使用已失效会话访问购物车并尝试下单 | 错误凭证不能获得有效登录身份；失效会话按契约拒绝受保护操作或要求重新认证；不能生成有效订单。提示文案为 P1 | 响应与页面、会话状态、订单查询结果 |
| T03 / P1 / 购物车边界 | 已知数量上限及删除规则；具备 UI 或合法测试接口入口 | 分别尝试数量 0、负数、非整数、上限、上限+1；删除最后一个商品后结算 | 按已确认规则拒绝、归一化或删除；上限符合规则；空购物车不能形成有效购买。未提供数量规则时只记录观察结果 | 输入及响应、购物车持久化快照、订单查询 |
| T04 / P0 / 重复下单与支付提交 | 固定购物车；已确认重复提交识别规则及库存策略 | 对同一次提交连续点击两次；条件允许时并发重复请求；对同一次支付尝试重复提交 | 按契约处理重复请求；不发生违反规则的重复扣款或库存变更。只有明确规定请求幂等时，才要求返回同一订单；不能把两个独立购买请求误判为重复 | 请求关联信息、订单数量、支付交易及扣款记录、库存变化 |
| T05 / P0 / 重复回调 | 新测试订单；一条有效成功通知；可重放；可查业务效果 | 投递一次有效通知；完成后顺序重放两次；再用新订单并发投递两份相同有效通知 | 同一交易的记账、履约、权益及库存效果按确认规则只生效一次；状态不回退；重复通知响应符合契约。多条接收日志本身不是失败 | 每次通知及响应、处理时间线、订单/交易快照、业务效果数量及关联记录 |
| T06 / P0 / 非法支付通知 | 已提供通知认证、金额、币种及关联规则；可构造测试通知 | 分别测试认证无效、金额不符、币种不符、未知交易/订单；每次只改变一个条件。测业务校验时使用有效测试认证 | 无效通知不能产生支付成功或资金、履约效果；按契约拒绝、隔离或告警。缺少契约或签名能力时阻塞 | 脱敏通知、响应、拒绝/隔离日志、业务状态及效果前后对比 |
| T07 / P0 / 跨账号访问 | A/B 各有自己的购物车和订单；确认普通账号隔离规则 | B 尝试通过已知测试入口读取或修改 A 的购物车、订单及支付信息 | 服务端拒绝越权；不泄露敏感数据；A 的记录没有变化。其他角色权限待矩阵提供后验证 | A/B 请求身份、响应、访问日志、A 的记录前后快照 |
| T08 / P0 / 金额篡改 | 可修改测试提交数据；服务端价格规则已确认 | 将购物车或订单提交中的价格、优惠或应付金额改低；尝试提交及发起支付 | 服务端按可信数据重算或拒绝；不能以篡改金额完成交易。具体字段缺失时阻塞接口用例 | 原始与修改后的请求、服务端价格明细、订单与支付金额 |
| T09 / P0 / 库存边界 | 商品库存设为 1；A/B 可并发下单；库存占用/扣减时点已确认 | A/B 各购买 1 件并同时提交；检查最终库存；再重复通知获成功订单 | 不超卖、不产生违反规则的负库存；失败一方没有不应产生的扣款；重复通知不重复扣库存。允许预售等例外须事先确认 | 两个账号的订单与交易结果、库存及变更记录 |
| T10 / P1 / 价格与可售状态变化 | A 已加购；可修改测试商品价格、库存或上下架状态 | 加购后改变一个条件，再结算和下单 | 按确认规则刷新价格、提示确认或拒绝下单；页面、订单与支付金额一致。接受错误价格或超卖升级 P0 | 变更前后商品记录、结算提示、订单金额 |
| T11 / P0 / 支付结果未知及延迟 | 可模拟支付响应超时或通知延迟；有查询与补偿规则 | 发起支付后制造响应超时；查询订单；延迟投递有效通知；按规则执行恢复 | 超时本身不能被当作确定失败或确定成功；恢复后按规则收敛；不因重试产生重复扣款。规则或时限缺失时待确认 | 支付侧记录、查询结果、通知时间线、恢复记录 |
| T12 / P1，资金异常升 P0 / 失败与取消 | 沙箱支持失败、取消；相关状态与重试规则已确认 | 分别触发失败和取消；返回订单查看状态；按规则重试 | 展示、可重试操作和库存释放符合规则；不得虚假显示已支付。不能假定取消后绝不会收到成功通知 | 沙箱结果、订单状态、操作入口及库存记录 |
| T13 / P0 / 通知乱序与竞争 | 可生成同一交易的合法不同状态通知；确认状态优先级、超时关闭和晚到通知规则 | 分别测试失败通知后成功、成功后失败、订单关闭与成功通知同时发生 | 按确认状态机处理；不因较旧通知错误回退；资金与订单一致，必要时进入规定补偿流程。规则缺失时待确认，不能自行决定最终状态 | 通知顺序与时间、状态变更历史、资金及补偿记录 |
| T14 / P1 / 空值与输入边界 | 登录、地址等输入契约及长度限制已提供 | 测必填项缺失、空白、长度上限及上限+1；提交缺少有效地址的订单 | 按契约校验；不保存无法履约的有效订单；敏感输入不出现在错误信息中 | 输入、错误反馈、持久化记录及脱敏日志 |

**5. 执行备注**

**建议的 30 分钟安排**

| 时间 | 工作 |
|---|---|
| 0–4 分钟 | 确认版本、环境、规则、测试数据和证据入口；检查回调重放能力。缺失项立即登记，不无限等待 |
| 4–9 分钟 | T01 全链路与金额、库存核对 |
| 9–11 分钟 | T02 错误登录与会话失效 |
| 11–14 分钟 | T04 重复提交 |
| 14–20 分钟 | T05 顺序及并发重复回调 |
| 20–23 分钟 | T06 非法通知 |
| 23–26 分钟 | T07 跨账号隔离 |
| 26–30 分钟 | 对账、整理证据、登记缺陷和未验证项，给出发布建议 |

这是依赖测试数据、入口和规则预先就绪的时间预算，不保证全部完成。某项阻塞时，可执行其他独立用例；替代用例通过不能抵消原 P0 阻塞。T03、T08–T14 默认留待补测，其中 P0 必须明确列入发布风险。

**判断与停止条件**

- 用例只有在操作完成、预期规则已确认、证据充分时才能记为“通过”；本初版全部为未执行。
- 发现重复扣款、错误金额支付、越权、重复履约或库存严重错误：暂停受影响的支付/下单测试，保存证据，按 P0 阻止放行。
- 缺少最终状态规则、通知契约或业务效果查询能力：相关 P0 无法验收，不能依据页面“支付成功”给出通过结论。
- 环境误连生产、可能产生真实扣款或破坏共享数据：停止相关操作，先恢复隔离条件。
- 30 分钟到期停止新增操作，完成记录；不得将未跑用例标成通过。
- 仅当规定的 P0 已验证通过、无未解决 P0，且验收规则和证据齐备时，才建议通过。否则给出“不建议放行”或“验证不充分”，由发布负责人决定是否接受剩余风险。

**当前未验证风险**

所有场景均未执行。尤其未排除：重复通知的并发竞争、资金与订单最终一致性、真实服务端权限隔离、金额篡改、库存竞争、通知乱序及延迟补偿。30 分钟冒烟也不能证明所有渠道、长时重试或生产配置均正确。

执行记录至少包括：用例 ID、版本/环境、实际操作、实际结果、通过/失败/阻塞/待确认/未执行、证据位置、缺陷及负责人。

**6. 待确认问题与下一步**

执行前优先补齐：

1. **接口契约**：实际字段、必填及边界、身份认证、重复提交识别规则、回调认证与应答、重试机制。
2. **支付状态规则**：成功判据、允许的状态转换、乱序优先级、收敛时限、超时关闭、晚到成功及补偿规则。
3. **权限矩阵**：普通用户、访客及其他实际角色对购物车、订单和支付信息的访问范围。
4. **业务及环境条件**：金额计算、库存时点、履约触发条件、沙箱账号、重放工具、只读证据入口。

下一步是将这些规则映射到上述用例，先确认 P0 的验收标准并准备独立测试订单，再执行 30 分钟验证。缺失项保留为阻塞或待确认；发布后补测不能替代发布前的资金与权限风险判断。
