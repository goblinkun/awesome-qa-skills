1. 任务理解

这是**待评审、未执行的功能测试初版**，覆盖登录 → 购物车 → 下单 → 支付 → 回调处理。目标是在 30 分钟发布验证窗口内，优先发现资金、订单、库存和访问权限方面的严重问题。

**已确认事实**

- 测试范围包含电商登录、购物车、下单、支付。
- 发布验证只有 30 分钟。
- 支付回调可能重复到达。
- 接口字段、角色权限矩阵、支付最终状态规则尚未提供。

**当前假设，执行前需确认**

- 有隔离测试环境、测试账号、商品及支付沙箱；允许产生测试订单。
- 可以通过支付模拟器产生有效、重复、失败和延迟回调，并查询相关日志。
- 暂以“金额一致、订单归属正确、重复通知不重复产生业务效果”为候选验收原则；这些不代表已提供的业务规则。
- 下文“成功、失败、处理中”表达业务含义，不是接口状态枚举。

缺少环境或回调模拟能力时，对应用例标记“阻塞”；缺少判断规则时标记“待确认”，不能算通过。本次仅设计方案，不进行环境访问或业务写入。

2. 风险和优先级

| 优先级 | 风险 | 取舍 |
|---|---|---|
| P0 | 重复回调导致重复记账、履约、扣库存或通知下游执行多次 | 必测同一有效回调串行重放及并发到达 |
| P0 | 支付金额、订单、交易对应错误；无效回调被接受 | 核对金额和归属；优先验证回调可信性 |
| P0 | 支付结果未知时被当作成功，或引导再次支付造成重复扣款 | 必测延迟、超时及恢复查询 |
| P0 | 用户可操作他人购物车、订单或支付记录 | 必测两个普通账号之间的隔离；完整角色矩阵待补 |
| P0 | 登录不可用、正常订单无法支付、非法数量或库存导致错误下单 | 覆盖一条完整正常流程及关键拒绝路径 |
| P1 | 数量边界、会话过期、价格变化、取消与回调竞争、失败后重试 | 首轮窗口外补测；其中资金及状态竞争风险较高，应优先追加 |
| P1 | 更多角色、优惠、运费、跨端和多支付渠道差异 | 暂缓；若属于本次变更范围或主要交易路径，提升为 P0 |

P0/P1 是当前风险排序，不是严重程度的永久标签。发现重复扣款、越权或错误履约时，无论来自哪条用例，都应按发布阻断处理。

3. 核心功能覆盖

| 流程 | 核心判断 | 数据与集成点 |
|---|---|---|
| 登录 | 有效账号可进入；错误凭据不能获得受保护访问 | 账号、会话、认证服务 |
| 购物车 | 商品和数量正确；非法值不能形成有效订单 | 商品、价格、库存、购物车服务 |
| 下单 | 订单归属、商品、金额正确；拒绝路径无有效订单副作用 | 订单服务、库存服务 |
| 支付 | 支付对应正确订单及金额；浏览器返回不能单独作为支付证据 | 支付沙箱、支付记录 |
| 回调 | 校验来源及关联；重复处理不重复产生业务效果 | 回调处理、消息队列、记账及履约服务 |

准备账号 A/B、可售商品 X、不可售商品 Y、可控制库存的商品 Z，以及可独立使用的订单。金额先选无优惠、费用已知的组合，避免未定义的计价规则影响首轮判断。

证据统一包含：版本、环境、时间、用例编号、订单与交易关联标识、脱敏请求/响应、页面截图、相关日志和处理前后记录。逻辑名称不预设真实接口字段。缺少日志或记录权限时，注明证据缺口，不能仅凭页面判断后端处理正确。

5. 执行备注

30 分钟安排如下：

| 时间 | 工作 |
|---|---|
| 0–3 分钟 | 核对版本、环境、账号、数据、回调工具及判断规则；登记阻塞项 |
| 3–9 分钟 | C01 |
| 9–15 分钟 | C02 |
| 15–18 分钟 | C03 |
| 18–22 分钟 | C04 |
| 22–25 分钟 | C05 |
| 25–27 分钟 | C06 |
| 27–30 分钟 | 汇总证据、失败与阻塞，给出发布结论 |

若用例超时，保留已经取得的证据，将剩余项标记未执行；不能压缩重复回调核查，也不能把未执行项记为通过。

**停止条件**

- 环境指向生产、测试隔离失效或出现真实资金影响：停止执行。
- 发现重复资金处理、错误订单支付成功、越权修改或错误履约：停止发布推进，保留现场，报告发布阻断；安全隔离的诊断可继续。
- 接口契约缺失导致无法构造有效输入：停止该用例，标记阻塞。
- 最终状态规则或收敛时限缺失：可以记录观察，但停止作出“状态正确”的结论。
- 30 分钟到达：结束验证窗口，列明剩余项。

发布建议的候选门槛是：P0 全部执行、判断规则明确、关键证据齐全且无失败。**P0 阻塞、待确认或未执行时，不能给出验证通过结论**；需由发布负责人基于明确剩余风险决定延期或接受风险。

**未验证风险**

当前全部用例均未执行。首轮方案还不覆盖持续高并发、多渠道差异、完整角色权限、退款对账、故障恢复及优惠组合。重复回调的功能验证也不能替代长期重试、队列积压和持久化故障验证。

6. 待确认问题

执行前必须补齐：

- **接口契约**：入口、认证方式、必填字段、类型、错误响应、数量和金额约束。
- **角色权限矩阵**：普通用户及其他角色的资源归属、读写权限。
- **支付规则**：可信结果来源、合法状态转换、最终状态判定、回调关联与去重依据、乱序处理、取消/支付竞争规则、查询恢复方式和收敛时限。
- **执行条件**：测试环境、发布版本与变更范围、数据准备、沙箱能力、日志及记录查询入口。

下一步先把这些信息映射进用例，确定可复用的测试数据和回调脚本，再开展 30 分钟验证。窗口后优先补测 C12、C11 和完整权限矩阵，并输出逐例结果及发布建议。
