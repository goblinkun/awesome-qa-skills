当前架构具备部分测试条件：隔离主题可以支持消息测试，回调模拟器可以支持部分异步场景。但故障路径缺少控制入口，完整隔离、支付结果闭环和复现能力也缺少证据。**本次交付是可执行的评审与验证方案；未运行系统测试，不能认定改进有效或架构已通过。**

**1. 任务理解与范围**

评审订单服务、消息队列、支付适配器、外部支付商及回调链路，目标是让成功、失败和结果不确定的场景能够安全触发、可靠判定并重复验证。本方案限定在本地或隔离测试环境，不涉及生产写入。

**2. 输入审计**

以下是用户提供的输入事实，尚未通过架构制品或执行记录独立核验：

| 编号 | 输入事实 | 能支持的判断及其边界 |
|---|---|---|
| F1 | 订单服务通过消息队列调用支付适配器 | 存在异步消息边界；投递、确认和重试语义未知 |
| F2 | 适配器依赖外部支付商 | 存在外部依赖；协议、幂等和查询能力未知 |
| F3 | 沙箱有回调模拟器 | 有回调刺激来源；延迟、重复、乱序、签名和自动化能力未知 |
| F4 | 没有故障注入入口；队列可配置隔离主题 | 故障控制能力存在缺口；主题隔离不能证明整个链路隔离 |

依赖拓扑可暂时表示为：

`订单服务 → 消息队列 → 支付适配器 → 外部支付商`

回调接收方、支付结果回传订单服务的路径、持久化位置均未知，不能补画成已确认链路。

待核验材料包括：部署与数据流图、消息及支付接口契约、订单与支付状态机、消费确认和重试配置、幂等设计、沙箱说明、回调模拟器能力、日志与历史运行记录。材料还需附版本、日期和环境，否则不能判断是否对应当前部署。

**3. 风险与优先级**

优先级按业务影响和当前可探测性排序；输入不足以估算发生概率。

| 优先级 | 失败模型 | 排序依据 |
|---|---|---|
| P0 | 支付商已受理，但适配器超时；再次提交造成重复扣款，或订单被错误标为失败 | 潜在资金影响高；缺少故障入口使关键窗口难以验证。属于待验证风险，不是已发生缺陷 |
| P1 | 消费者处理后、确认前退出，消息再次投递；重复或乱序回调导致重复副作用或状态倒退 | F1、F3 支持相关边界存在，处理语义未知 |
| P1 | 测试消息、回调或数据进入其他测试实例或真实业务链路 | F4 仅提供主题隔离能力，其他边界无证据 |
| P1 | 事件丢失或延迟后，无法定位链路、确认最终结果 | 关联追踪、结果回传和补偿路径未知 |
| P2 | 沙箱与部署环境配置差异、时间依赖导致测试偶发失败 | 环境清单和复现记录缺失 |
| P3 | 场景依赖人工操作，运行结果难以归档和比较 | 自动化入口未知，先核实已有资产再补建设 |

**4. 核心分析与执行项**

当前测试性评估采用“部分具备／明确缺口／未知”，不计算缺乏依据的数值总分：

| 维度 | 当前评估 | 改进及验证重点 |
|---|---|---|
| 组件与异步边界 | 部分明确 | 明确发布、消费、外部受理、回调、状态落库、结果通知的责任与确认点 |
| 测试接缝与替身 | 未知 | 核验支付客户端、回调接收端、时钟和状态查询是否可独立替换或控制 |
| 隔离 | 部分具备 | 将主题隔离扩展到消费组、存储、凭据、回调地址和外部支付账号 |
| 故障注入 | 明确缺口 | 增加仅用于隔离环境的故障控制机制，并验证实际命中 |
| 可观察性 | 未知 | 跨边界关联事件，并提供最终状态及副作用证据 |
| 可控制性 | 部分具备 | 核实模拟器能力；补足超时、退出、暂停消费等控制 |
| 确定性 | 未知 | 固定输入和故障时序，等待明确状态，避免任意休眠 |
| 环境复现、数据、自动化 | 未知 | 固定版本与配置，提供独立数据和机器可读取的运行产物 |

建议按以下顺序实施。成本是相对估计，需在核验现有资产后调整。

| 改进项 | 最小实现与价值 | 成本／负责人建议 | 验证证据 |
|---|---|---|---|
| P0：确定支付状态与重试契约 | 明确“结果未知”的处理、幂等范围、查询或对账路径，建立资金一致性的测试判据 | 中；订单、支付负责人及业务方共同决定 | 状态机、接口契约、超时后处理记录 |
| P0：支付依赖接缝 | 优先复用现有支付客户端边界，以配置切换受控替身；支持拒绝、超时、已受理但响应丢失 | 中；支付适配器负责人 | 调用计数、幂等键、替身受理账本、最终状态 |
| P1：异步故障控制 | 测试消费者支持暂停、恢复，以及在指定处理点退出；用测试代理控制连接和响应 | 中至高；服务与平台负责人 | 故障命中记录、确认时间线、重新投递记录 |
| P1：完整隔离 | 每次运行使用独立主题与消费组，并隔离数据命名空间、账号、凭据和回调路由 | 中；平台负责人 | 生效配置、路由记录、跨运行污染检查 |
| P1：链路证据 | 关联订单、支付尝试、消息、回调及测试运行；记录状态迁移、重试、确认和异常 | 中；各服务负责人 | 脱敏事件时间线、状态查询、支付侧记录 |
| P2：复现与自动化 | 固定镜像和配置；提供数据准备、场景触发、状态等待、证据导出及清理入口 | 低至中；测试与平台负责人 | 环境清单、运行命令、输入、退出码、产物及清理结果 |

这些标识和入口均为**建议**，不代表系统已经存在相应字段或 API。故障机制应只部署在隔离环境，通过受限配置或测试编排控制；不得绕过鉴权或增加生产公共后门。

替身分层使用：

- **组件测试**：用受控支付替身验证状态机和重试逻辑；必要时替换时钟。模拟器成功不能证明真实支付协议兼容。
- **消息集成测试**：使用真实消息队列及隔离主题，验证确认、重新投递、消费组和路由。内存队列不能提供这些证据。
- **回调测试**：复用现有模拟器，先核实签名、重复、乱序和延迟能力；缺失能力再补充。
- **沙箱契约测试**：用支付商沙箱核验真实协议、签名、错误映射和幂等行为。替身行为需与契约及沙箱证据对照。

下面的场景可作为第一批执行清单。执行前，业务与技术负责人应批准状态机、结果收敛期限 `T`、重试上限 `R` 和人工接管条件；它们目前没有输入依据。

| 场景 | 前置条件与刺激 | 预期结果／判断标准 | 必须保留的证据 |
|---|---|---|---|
| 成功闭环 | 独立订单；发送支付消息；触发合法成功回调 | 在 `T` 内达到约定状态；完成通知路径可追溯 | 消息、调用、回调、状态迁移及最终查询 |
| 重复消息 | 同一业务支付请求重复投递；记录每次消费 | 同一业务支付只产生一次有效支付副作用；后续投递按契约处理 | 消费记录、幂等记录、受理账本；仅看调用次数不足 |
| 已受理但响应丢失 | 替身先记录受理，再丢弃响应；触发恢复或重试 | 不误判为确定失败；通过批准的查询、对账或人工路径收敛，无重复扣款 | 故障命中、受理记录、后续调用及收敛结果 |
| 处理后确认前退出 | 在约定提交点后、队列确认前终止测试消费者，再重启 | 按队列契约恢复；重复处理不重复产生业务副作用 | 提交点、退出、确认、重投和最终副作用记录 |
| 重复与乱序回调 | 先确认模拟器具备能力；按指定顺序发送合法回调 | 遵循批准的状态迁移规则，不因重复事件重复处理，不非法倒退 | 回调序列、处理决定、状态迁移 |
| 无效回调 | 构造错误签名、未知支付标识及属于另一运行的回调 | 无效事件不改变业务状态，拒绝原因可追踪 | 脱敏校验日志、状态前后对照 |
| 外部拒绝与持续超时 | 分别返回契约规定的拒绝、持续无响应，推进至重试边界 | 拒绝和未知结果分别处理；重试不超过 `R`，按约定停止或转人工 | 错误映射、重试时间线、接管记录 |
| 双运行隔离与重放 | 两套独立资源并行执行；随后用相同版本、输入和故障序列重放 | 消息、回调与数据不串扰；关键业务结果一致 | 两套配置、路由和数据记录、重放差异报告 |

确定性应控制输入、故障触发点和可控时间，使用“已消费／已受理／已落库”等状态屏障等待结果。真实队列和外部沙箱仍有调度及网络波动，不能假设全局事件顺序，也不能仅凭一次通过认定稳定。

每次运行需归档：服务与镜像版本、队列版本及投递配置、主题和消费组、超时与重试配置、沙箱能力或版本说明、数据库迁移版本、脱敏数据种子、故障序列和完整执行结果。

**5. 阻塞条件与剩余风险**

以下条件阻塞对应测试结论或发布判断，不妨碍先开展组件验证：

- 未批准状态机、幂等范围和未知结果处理规则：无法判定资金相关场景是否通过。
- 无法证明外部账号、凭据和回调路由隔离：停止真实外部调用测试。
- 未证明故障命中指定窗口：不能声称恢复机制已经验证。
- 缺少支付侧受理或副作用证据：只能确认内部状态，不能确认不存在重复扣款。

执行中若出现跨环境流量、重复支付副作用或超过 `T` 仍无法确认结果，应停止该场景，保留证据并按批准流程人工接管；不要自动退款、删数据或盲目重试。

残余风险包括沙箱与真实支付商行为差异、替身契约漂移、长尾时序和规模效应。可用契约核验及更广泛的隔离测试降低风险，但接受哪些差异、何时允许发布，仍需业务、支付及发布负责人明确决定。

**6. 下一步与待确认事项**

最小推进顺序是：

1. 架构负责人补齐结果回传、回调和持久化路径；支付负责人确认状态、幂等及查询契约。
2. 平台负责人验证主题以外的隔离边界；测试负责人核实回调模拟器的实际能力。
3. 在受控支付替身上先执行“成功闭环、重复消息、已受理但响应丢失”，归档完整证据。
4. 再验证真实队列的退出恢复、回调乱序及双运行隔离，最后进行沙箱契约核验。

人类需决定的事项是：未知支付结果的业务处理、可接受的收敛与重试边界、改造预算、发布门槛和残余风险接受范围。普通测试接缝和证据采集实现，可由工程负责人按现有架构自行选择。
