## 1. 任务理解

这是**待执行的功能测试初版**，覆盖登录 → 购物车 → 下单 → 支付 → 支付回调 → 订单结果。本次仅设计方案，**未执行测试，也不代表发布已通过验证**。

**已确认事实**

- 发布验证窗口只有 30 分钟。
- 支付回调可能重复到达。
- 尚未提供接口字段、角色权限矩阵、支付最终状态规则。

**当前假设，需确认后作为判定依据**

- 验证在隔离测试环境进行，可使用测试账号、测试商品、支付沙箱及回调重放工具。
- 可准备两个普通用户 A/B，以及可售、库存不足、不可售商品；能查看订单、支付流水和回调处理记录。
- 同一笔支付的重复通知不应重复产生业务效果，如重复入账、扣库存、发放权益或触发履约。具体有哪些效果，按系统实际实现确定。
- 普通用户只能访问、操作授权范围内的购物车、订单和支付信息。具体角色差异等待权限矩阵确认。
- 可通过已批准的规则识别支付成功、失败及待处理状态；**不预设实际状态名、接口字段、错误码、重试次数或状态迁移规则**。

接口层用例先描述业务操作。拿到真实接口契约后，补齐请求地址、字段、认证方式和回调构造方法；不得凭空生成支付请求或回调。

## 2. 风险和优先级

这里的 P0/P1 表示**验证优先级**，不是已发现缺陷的等级。

| 优先级 | 风险 | 30 分钟取舍 |
|---|---|---|
| P0 | 核心链路无法完成；商品、金额、订单或支付交易关联错误 | 必须跑一条完整链路，并核对服务端结果 |
| P0 | 重复、并发回调导致重复业务效果 | 最大时间投入；检查结果及副作用次数 |
| P0 | 支付失败、超时或仅前端返回成功，却产生成功业务效果 | 选一个可稳定注入的异常；不能只看页面提示 |
| P0 | 登录隔离失效、越权访问或操作他人订单/支付 | 覆盖未登录和 A/B 两个普通用户；完整角色覆盖后补 |
| P0 | 无效回调被接受；迟到、乱序通知产生错误状态迁移 | 无效回调优先验证；状态迁移因规则缺失可能阻塞 |
| P1 | 购物车持久化、数量边界、库存/价格变化、重复提交 | 在 P0 完成后抽查；若出现资金、重复订单或库存损坏，升级为 P0 |
| P1 | 更多角色、促销组合、浏览器兼容、长时间重试与恢复 | 本窗口不全面覆盖，登记未验证风险 |

**30 分钟执行安排**

前提是账号、数据、工具和判定规则已提前准备。准备不足时，不能把计划时长当成完成承诺。

| 时间 | 内容 |
|---|---|
| 0–3 分钟 | 检查环境、数据、规则和证据入口，确定可执行用例 |
| 3–8 分钟 | 完整正常链路：登录、购物车、下单、支付 |
| 8–16 分钟 | 串行重复回调、并发重复回调、副作用核对 |
| 16–21 分钟 | 支付异常、无效回调；有规则时检查迟到/乱序 |
| 21–25 分钟 | 未登录访问、A/B 用户隔离 |
| 25–28 分钟 | 购物车与数量/库存边界抽查 |
| 28–30 分钟 | 汇总结果、阻塞项、证据及发布建议 |

P0 超时应占用 P1 时间。**30 分钟到点仍有 P0 未验证，应报告验证不充分，不能默认通过。**

## 3. 核心功能覆盖

| 流程 | 核心覆盖 | 数据与集成点 |
|---|---|---|
| 登录 | 正确/错误凭据、退出或失效会话、用户隔离 | 账号、认证服务、会话 |
| 购物车 | 添加、修改、删除、重新进入、数量及可售性边界 | 商品服务、价格、库存、购物车存储 |
| 下单 | 商品与金额一致、重复提交、库存/价格变化、归属权限 | 订单服务、库存；促销/运费仅在实际存在时核对 |
| 支付 | 发起支付、正常返回、失败/超时、订单与交易关联 | 支付沙箱、订单、支付流水 |
| 回调与结果 | 有效性校验、重复与并发、迟到/乱序、状态收敛、副作用次数 | 回调处理、订单/支付状态、实际存在的下游服务 |

金额计算、库存扣减时机、订单失效、退款、补偿、支付重试和最终状态都需要业务规则。缺少规则时只能记录观测，不能据此认定通过。

## 4. 关键场景清单

**执行约定**

- 每项使用独立数据或记录明确基线，避免前一个用例污染后一个。
- 涉及回调时，使用沙箱产生的有效通知及受控重放工具；不得手写猜测字段。
- “规则”指已批准的需求、接口契约或状态迁移规则。
- 结果记录为：通过、失败、阻塞、未执行。没有判定依据记为**阻塞**。
- 以下每项证据均应带用例编号、时间、环境/版本、关联订单/交易标识，并脱敏。

| 编号 / 优先级 / 类型 | 前置条件 | 操作 | 预期判断 | 证据 |
|---|---|---|---|---|
| L1 / P0 / 正常、异常 | 有效账号；独立未登录会话；已知登录规则 | 正确凭据登录；退出后用错误凭据登录 | 正确凭据进入对应身份；错误凭据不建立可访问受保护资源的会话；提示按规则判断 | 脱敏请求/响应、会话身份、受保护资源访问结果 |
| L2 / P0 / 异常 | 有效会话；明确退出或过期行为 | 退出或令会话按规则失效；刷新页面，并用原会话访问受保护操作 | 失效会话不能继续执行受保护操作；具体失效时机须按契约判断 | 失效前后请求、服务端认证结果、会话记录 |
| C1 / P0 主链路；P1 补充 / 正常 | A 登录；可售商品；记录购物车与价格基线 | 添加商品、改变合法数量；删除再添加；重新进入购物车 | 商品、数量与操作一致；金额符合规则；持久化行为按规则判断 | 操作前后购物车、服务端结果、价格计算依据 |
| O1 / P0 / 正常 | C1 的合法购物车；满足实际必填结算条件 | 提交订单，查看订单详情 | 订单归属正确；商品、数量、价格、费用及应付金额符合规则；订单标识可用于关联支付 | 购物车快照、订单请求/响应、订单记录、金额核算 |
| P1 / P0 / 正常 | O1 订单；支付沙箱；成功结果与收敛时间规则已确认 | 发起支付并完成沙箱成功流程；等待回调处理，刷新订单 | 支付交易关联正确；金额/币种符合实际契约；在规定时间内达到批准结果，业务效果符合规则 | 沙箱交易结果、回调记录、订单/支付记录、业务效果记录 |
| P2 / P0 / 异常 | 独立订单；可稳定模拟失败或超时；规则已确认 | 注入失败或超时；查看页面及服务端；仅按规则执行后续重试/查询 | 不因页面跳转或请求超时误判成功；失败或不确定状态按规则处理；未经确认成功不产生成功业务效果 | 注入结果、前端提示、服务端状态时间线、业务效果记录 |
| R1 / P0 / 异常 | 独立订单；有效回调；已保存处理前基线；明确幂等范围 | 首次投递后记录结果；将同一有效通知串行重放两次 | 第 2、3 次不重复产生业务效果；状态符合规则；响应及重试语义按契约判断，不预设错误码 | 三次投递与处理记录、前后状态、入账/库存/权益/履约等实际效果次数 |
| R2 / P0 / 边界 | 另一独立订单；尚未处理的有效回调；工具支持并发 | 同时投递两份相同通知；等待规定处理窗口结束 | 并发情况下仍只产生一次对应业务效果；最终状态一致，无遗留异常处理中记录 | 投递与处理时间、处理追踪、状态记录、副作用计数 |
| R3 / P0 / 异常 | 沙箱回调契约、校验方式、可变更范围已提供 | 用受控工具构造一条校验不通过通知；检查订单与支付 | 无效通知不改变支付结果或触发成功业务效果；拒绝方式按契约判断 | 脱敏通知、校验失败记录、处理前后状态及效果 |
| R4 / P0 / 边界、异常 | 提供允许的状态迁移、取消/超时规则及通知顺序语义 | 按规则构造“成功后旧通知”和“订单取消/超时后迟到成功”两个独立场景 | 不发生规则禁止的状态迁移；资金、订单及补偿结果按批准规则处理；**规则缺失则阻塞，不猜测最终状态** | 通知顺序、状态时间线、资金与补偿记录、引用的迁移规则 |
| A1 / P0 / 异常 | 独立未登录会话；A/B 各有购物车和订单；普通用户权限边界已确认 | 未登录访问受保护操作；A 使用 B 的资源标识尝试读取/修改购物车、订单、支付 | 服务端拒绝未授权操作；不泄露受限数据，不修改 B 的资源；更细角色差异等待矩阵 | 请求/响应、认证身份、B 的前后数据；不可只以页面隐藏判断 |
| O2 / P1 / 边界 | 明确下单幂等契约；支持受控重复提交 | 双击提交；模拟响应未收到后重试同一业务请求 | 订单数量及库存占用符合契约；若不允许重复下单，不产生额外有效订单 | 请求关联、订单数量、库存/占用记录 |
| B1 / P1 / 边界 | 数量下限 L、上限 U、字段格式已提供 | 分别尝试 L−1、L、U、U+1；另检查空值及契约定义的非法格式 | 合法边界可处理；非法输入在服务端被拒绝且不污染购物车/订单；提示按规则判断 | 输入、校验结果、购物车/订单前后记录 |
| B2 / P1，资金/库存异常升级 P0 / 异常、边界 | 已知价格变化、库存不足、下架后的结算规则 | 加入购物车后分别改变价格、降低库存、下架商品，再提交订单 | 按规则重新校验或要求确认；不使用未经规则允许的金额或库存结果 | 商品变更前后记录、结算响应、订单金额、库存结果 |

重复回调还需确认：支付方是否可能用**不同通知标识表示同一笔支付**。若存在，增加“不同通知标识、同一支付交易”的重复效果检查，不能仅凭相同消息重放通过就认定幂等完整。

## 5. 执行备注

**证据与通过标准**

记录格式建议为：

`用例编号｜版本/环境｜前置数据｜实际操作｜实际结果｜判定依据｜结果｜证据位置｜缺陷/阻塞项`

支付相关用例必须核对服务端与业务效果。页面显示“支付成功”、收到一次成功响应，或日志出现“已处理”，均不足以单独证明正确。异步结果按已批准时间窗观察；时间窗未提供时，不擅自定义等待多久即可通过。

**停止条件**

- 环境无法确认隔离、数据不可控、支付沙箱或重放工具不可用：停止相关操作，记录阻塞。
- 缺少字段契约、权限边界或状态规则，无法安全构造输入或判断结果：停止该用例的正式判定，其他独立用例继续。
- 发现重复资金/业务效果、金额或交易关联错误、越权、无效回调被接受：停止扩大相关操作，保留证据并登记 P0 缺陷。
- 环境异常导致结果不可解释：标记阻塞，不归为产品通过或失败。
- 30 分钟结束：停止执行并出具当前结果，未运行项保持“未执行”。

发布建议“通过”需满足所有约定必验 P0 已执行并通过、证据完整，且无 P0 缺陷或阻塞。P1 未执行项要明确列出，并由发布负责人决定是否接受风险。

**尚未验证的风险**

本方案所有用例均未执行。30 分钟抽样还不能证明完整角色权限、所有回调顺序、长时间状态收敛、支付重试/退款/补偿、多订单并发、促销组合或多端兼容正确。缺失的最终状态规则尤其影响支付结果与迟到通知的判定。

## 6. 待确认问题

执行前优先补齐以下信息：

1. **接口契约**：认证、购物车、下单、支付及回调的真实字段、校验方式、关联标识、幂等范围和响应语义。
2. **权限矩阵**：访客、普通用户及其他实际角色对购物车、订单、支付的读写权限。
3. **支付规则**：状态集合、允许迁移、最终状态判据、收敛时间窗；失败/超时、重复/乱序/迟到通知、取消订单后付款的处理规则。
4. **业务与环境**：金额算法、数量/库存边界、扣减和履约时机；沙箱、重放工具、测试数据及证据入口。

下一步是将这些信息映射到用例，解除阻塞项，提前准备独立测试数据与有效通知，再按 30 分钟安排执行。若发布前仍缺少支付最终状态规则及必要契约，应明确报告：**支付 P0 验证依据不足，无法给出完整通过结论。**
