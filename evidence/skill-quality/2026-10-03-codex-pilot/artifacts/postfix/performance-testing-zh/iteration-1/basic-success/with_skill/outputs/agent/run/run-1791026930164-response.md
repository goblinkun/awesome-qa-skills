### 1. 任务理解

为订单查询、下单设计 SIT 性能测试，验证促销峰值 **800 RPS 下 P95 < 500ms、错误率 < 0.1%**，重点检查支付回调排队是否影响响应和订单状态更新。

**已确认：**业务范围、峰值、性能目标、SIT 环境及 APM 可用；支付回调排队是已知风险，具体瓶颈尚未确认。

**当前假设，执行前需核实：**

- 800 RPS 指查询与下单 API 的合计请求率，支付回调流量单独计算。
- 暂按查询 80%、下单 20% 分配，即峰值查询 640 RPS、下单 160 RPS；实际执行优先采用业务流量比例。
- P95 和错误率要求分别适用于查询、下单，避免总体指标掩盖下单问题。
- 支付回调异步完成；API 响应时间不代表订单支付状态已更新，后者需要独立目标。
- SIT 容量与生产的差异未知，因此结果只能直接说明 SIT 的表现。

### 2. 性能风险和优先级

| 优先级 | 风险 | 验证重点 |
|---|---|---|
| P0 | 回调处理速率低于到达速率，积压持续增长 | 队列深度、最老消息年龄、消费速率、订单状态更新延迟 |
| P0 | 回调与查询、下单争用资源 | 积压时 API 延迟、错误率及 APM 中数据库、线程池等等待 |
| P0 | 回调超时、重试或重复投递造成业务异常 | 无重复业务处理、无订单丢失、恢复后状态一致 |
| P1 | 查询热点及下单写入竞争 | 热门订单访问、数据库锁等待、慢查询、连接池饱和 |
| P1 | 长时间运行逐渐退化 | 内存、连接、队列及延迟趋势 |

### 3. 建议测试类型

选择**基线、阶梯负载、突增、稳定性测试**，并加入专门的回调积压与恢复场景。

压力测试用于定位容量边界，安排在目标负载验证之后。若 SIT 缺少可隔离资源或停止机制，先省略压力测试，并在报告中说明尚未确认容量上限。

### 4. 场景方案

以下流量、时长和故障参数均为**初版建议值**。

| 场景 | 负载与执行方式 | 观察及判定重点 |
|---|---|---|
| 基线，P1 | 50 RPS，预热 5 分钟，测量 10 分钟；分别覆盖查询、下单及混合交易 | 建立正常延迟和资源基线，确认脚本、数据、APM 链路有效 |
| 阶梯负载，P0 | 混合流量依次为 200、400、600、800 RPS；每级保持 10 分钟，800 RPS 保持 30 分钟 | 各交易是否达标；回调积压是否持续增长；定位首次退化的负载级别 |
| 回调积压与恢复，P0 | 维持 800 RPS，先测正常回调；再在 SIT 中将回调消费能力临时降至低于到达速率，保持 5 分钟，然后恢复，观察至少 15 分钟 | API 是否受拖累；队列能否清空；重试是否放大流量；订单状态是否最终一致 |
| 突增，P0 | 从 200 RPS 在 10 秒内升至 800 RPS，保持 15 分钟，再降回 200 RPS；重复 3 次 | 突增期间延迟、错误及积压变化，降载后的恢复速度 |
| 稳定性，P1 | 800 RPS 持续 2 小时，保留与下单关联的回调流量 | 延迟和资源是否逐渐退化；队列年龄、内存或连接数是否持续增长 |
| 压力／容量，P1 | 从 800 RPS 起，每级增加 160 RPS，保持 10 分钟，直到首次不达标或触发停止条件 | 找出最大持续达标负载及首个瓶颈，降载后验证恢复 |

**交易和数据设计：**

- 查询覆盖实际支持的主要查询路径；包含存在／不存在订单、冷热数据及符合业务情况的结果规模。
- 下单使用独立测试用户和足够的订单数据，校验成功响应对应真实订单。
- 回调使用 SIT 测试链路或受控模拟，覆盖正常、延迟、重复及重试；回调量根据实际支付比例和延迟分布生成。不能直接把全部下单请求等同于成功支付。
- 记录订单标识、回调标识与链路标识，抽样追踪从下单到支付状态更新的完整过程。

### 5. 指标和退出标准

**800 RPS 验收：**

- 查询、下单各自 **P95 < 500ms、错误率 < 0.1%**，同时检查总体结果及分钟级波动。
- 错误包括非预期响应、超时、连接失败和业务失败；符合预期的业务拒绝单独统计，分类规则在执行前固定。
- 压测端未发出的计划请求必须单列；若实际流量未达到目标，不能宣称通过 800 RPS 验收。
- 正常峰值下，回调队列不得持续增长；订单及支付状态无丢失、无重复业务处理。

**回调建议阈值，需业务确认：**

- 正常负载下，从测试回调发出到订单状态可查询更新的 P95 < 5 秒。
- 消费能力恢复后，积压在 10 分钟内回到基线。
- 故障期间单独报告状态延迟和 API 指标，不与正常阶段混算。

**APM 与监控：**

同步采集 API P50/P95/P99、吞吐、错误分类，以及回调到达／消费速率、积压量、最老消息年龄、重试数；关联 CPU、内存、GC、线程池、连接池、数据库慢查询／锁等待和依赖耗时。APM 用于定位，压测端用于衡量请求延迟，避免采样遗漏影响结论。

**停止条件，建议值：**错误率连续 2 分钟 > 1%、队列达到预设保护水位、出现数据一致性异常，或影响其他 SIT 使用者。触发后停止增压并降载，保留监控及恢复证据。

### 6. 执行备注

- 执行前确认 SIT 服务规格、数据量、依赖和生产差异，划定测试时段及测试数据范围。
- 使用按到达率发压的方式，确保系统变慢时仍能施加目标 RPS；压测机必须有足够余量。
- 每轮明确标记预热、测量、故障和恢复窗口，统一时钟，保存脚本版本、参数、原始结果和 APM 证据。
- 报告分别解释“目标负载是否达标”“回调是否稳定”“故障后是否恢复”“容量边界在哪里”。共享资源等待必须有链路或监控证据支持，不能仅凭队列增长认定根因。
- 仍需补齐：真实交易比例、800 RPS 的统计口径、支付比例／重试规则、回调业务时限及 SIT 与生产的容量差异。

以上为测试方案，尚未执行压测；SIT 达标也不能直接换算为生产容量。
