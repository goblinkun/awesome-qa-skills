**半天优先验证“能登录、能找到商品、能下单、能正确付款”的交易闭环。优惠券和积分涉及金额时，不能直接跳过。** 以下为测试方案，尚未实际执行。

### 1. 任务理解

已知：功能包括登录、搜索、下单、支付、优惠券、积分、客服工单、后台报表；发版窗口只有半天。

**当前假设**：半天按 4 小时安排；核心业务是用户购买商品；测试账号、商品和支付测试环境可用。由于没有本次变更清单，以下优先级需结合实际改动调整。

### 2. 风险和优先级

| 优先级 | 保留范围 | 原因 |
|---|---|---|
| P0，发布必测 | 登录→搜索→下单→支付；金额、订单状态、重复提交、用户权限 | 直接影响成交、资金和数据归属 |
| 条件 P0 | 优惠券、积分抵扣；本次修改涉及的共享逻辑 | 会改变实付金额，错误可能造成损失 |
| 可降级 | 搜索高级功能、营销复杂组合、客服工单、后台报表完整回归 | 满足下述条件时，可减少覆盖而不阻断核心交易 |

### 3. 核心功能覆盖

保留一条完整成功链路，加上少量关键失败场景。优惠券和积分若上线可用且影响结算，各保留一次金额验证。

其他项的降级理由与条件：

- **搜索**：保留准确商品词查询；排序、筛选、模糊匹配可降级，前提是本次未修改相关逻辑，基本搜索能找到可售商品。
- **优惠券**：保留可用券抵扣、不可用券拒绝；复杂叠加和券种全组合可降级。只有本次不启用优惠券、也未修改相关逻辑时，才可暂缓专项验证。
- **积分**：若参与抵扣，保留余额不足和正确扣减；若仅用于奖励，可降级为一次到账冒烟，暂缓等级、历史明细等扩展场景。
- **客服工单**：可缩为“提交成功、客服可见”的冒烟，暂缓完整流转；前提是存在已确认可用的人工受理渠道，且本次未改工单权限或核心流转。
- **后台报表**：可缩为权限和一笔测试订单核对，暂缓全维度、导出、性能测试；前提是报表不承担本次结算、对账或合规必需职责。

**本次改动涉及上述功能，或历史上存在严重缺陷时，相应场景必须提升优先级。**

### 4. 关键场景清单

| 编号 | 优先级 | 操作与预期 |
|---|---|---|
| K1 | P0 | 有效账号登录→搜索可售商品→下单→测试支付成功；商品、数量、应付与实付一致，订单最终为已支付 |
| K2 | P0 | 错误凭据登录、未登录访问受保护流程；拒绝访问。用户 A 无法读取或支付用户 B 的订单 |
| K3 | P0 | 商品无库存时提交订单；明确拒绝，不产生可付款的无效订单。连续点击提交，不意外重复建单 |
| K4 | P0 | 支付失败或取消后重试；失败时不能标为已支付，成功后订单与支付记录一致 |
| K5 | P0 | 在测试环境重复或延迟通知支付结果；不重复扣款、重复记账，页面与订单最终状态一致 |
| K6 | 条件 P0 | 使用有效券；核对应付与实付。过期券或未达到门槛的券不生效，不错误消耗券 |
| K7 | 条件 P0 | 积分抵扣达到可用余额边界、超过余额；合法抵扣金额正确，超额被拒绝，失败或重试不重复扣积分 |

K5 需要支付沙箱或已有模拟能力；无法执行时，应明确记录资金一致性未验证，不能标记通过。

### 5. 执行备注

按 4 小时分配：

- **30 分钟**：核对变更范围，准备普通用户 A/B、必要的后台账号、可售及无库存商品、券与积分数据。
- **90 分钟**：执行成功链路与权限检查。
- **60 分钟**：执行下单边界、支付失败及重复通知。
- **45 分钟**：按风险执行营销金额验证或降级冒烟。
- **15 分钟**：复测、记录结果并形成发布结论。

集成检查聚焦商品/库存、订单、支付；启用营销时增加优惠计算与资产扣减。仅在测试环境执行。

**发布门槛**：所有适用 P0 通过。金额错误、重复扣款、支付与订单状态不一致、越权访问均阻断发布。若缺陷修复挤占时间，先撤掉降级项，保留 P0 复测。
