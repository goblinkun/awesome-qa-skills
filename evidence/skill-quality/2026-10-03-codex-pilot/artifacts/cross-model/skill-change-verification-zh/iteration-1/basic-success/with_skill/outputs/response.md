# 验证报告

## 变更分类

Prompt 属于内容与运行时行为变更；`eval.yaml` 属于评测用例与结构变更。两者都需要检查，因为评测通过也可能遗漏 Prompt 的实际使用场景。

## 已执行检查

| 命令 | 证据等级 | 结果 |
| --- | --- | --- |
| 读取本地 `skill-change-verification` 说明及其 Prompt | Static | 确认了验证分级和结论边界 |
| 查找工作区中的待验证文件 | Static | 未发现本次变更的 Prompt 或 `eval.yaml` |

## 未执行检查

| 项目 | 原因 | 风险 |
| --- | --- | --- |
| 检查 Prompt 内容、`eval.yaml` 格式及用例覆盖 | 未提供变更文件 | 无法判断用例是否覆盖新行为和边界情况 |
| `skill-up validate` | 当前没有可验证的变更文件 | 无法声称评测通过 |
| 用真实输入运行变更后的 Prompt，检查输出并人工审阅 | 当前没有目标 Skill 和运行样例 | 无法判断运行时行为与语义是否符合预期 |

## 可以声称

验证应覆盖 **Prompt 内容审查 → `eval.yaml` 结构与用例审查 → `skill-up validate` → 代表性输入的运行时验证与人工审阅**。`skill-up validate` 提供评测证据，不能替代实际运行后的行为检查。

## 不能声称

目前不能声称该变更已通过验证，或 Prompt 在运行时表现正确。

## 残余风险

待取得实际变更文件和运行样例后，才能确认评测用例的覆盖范围及运行时结果。
