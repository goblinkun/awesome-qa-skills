### 1. 任务理解

**已确认事实：**新版本增加“积分兑换”；没有原型和接口文档。

**当前假设：**

- 用户用自己的积分兑换某种权益，兑换成功后扣除积分并交付权益。
- 可以观察积分余额、兑换结果及相关记录；具体入口和记录形式待确认。
- 库存、兑换次数限制、有效期、撤销退款等机制尚未确认，相关场景作为条件用例。

本初版用于需求评审和后续执行，**尚未执行测试，不代表功能已通过验收**。

### 2. 风险和优先级

| 优先级 | 重点风险 |
|---|---|
| P0 | 多扣积分、重复发放、扣分后权益丢失、余额不足仍兑换、操作他人账户 |
| P1 | 库存或限额失效、边界判断错误、结果与记录不一致 |
| P2 | 展示、提示和操作体验问题 |

P0 应作为发布前必测项。规则未确认时，相关用例先标记“待确认预期”。

### 3. 核心功能覆盖

暂定主流程：

**查看积分及可兑换项 → 选择兑换项 → 确认兑换 → 处理扣分和权益发放 → 查看结果及记录。**

覆盖积分校验、成功兑换、失败与恢复、重复提交、账户隔离、数据一致性；若存在库存、限额、有效期等机制，再执行对应条件用例。

数据准备：

- 两个独立用户 A、B，以及未登录状态。
- 选一个实际兑换项，用 `C` 表示其所需积分，仅为测试记号。
- 余额分别为 `0`、小于 `C`、等于 `C`、大于 `C` 的账户。整数积分可选 `C−1/C/C+1`；小数积分需按最小精度取值。
- 若适用，准备库存为 0、1，以及限额剩余为 0、1 的兑换项。
- 准备可观察的积分账务记录和权益交付结果，不预设接口或字段。

### 4. 关键场景清单

下表预期基于上述假设；涉及具体业务规则的部分需确认后定稿。

| 编号 / 优先级 | 前置与操作 | 检查点 / 暂定预期 |
|---|---|---|
| T01 / P0 | A 积分大于 `C`，完成一次兑换 | 成功兑换一次；扣除 `C`；权益发放一次；余额、兑换记录、权益结果一致 |
| T02 / P0 | A 积分恰好等于 `C`，完成兑换 | 若无额外条件，应成功；余额为 0；权益发放一次 |
| T03 / P0 | A 积分小于 `C` 或为 0，尝试兑换 | 拒绝兑换；不扣分、不发权益；提示能说明原因 |
| T04 / P0 | 快速连点确认，或对同一兑换操作重复提交 | 同一操作不能重复扣分或重复发放；独立新兑换是否允许按限额规则判断 |
| T05 / P0 | A 仅够兑换一次，在两个会话中同时兑换 | 最多一次成功；余额不为负；成功次数、扣分和发放次数一致 |
| T06 / P0 | 提交后模拟断网或响应超时，恢复后查看并重试 | 结果可查询或恢复；同一操作不重复处理；最终账务与权益一致，不能仅凭超时判定失败 |
| T07 / P0 | 在受控环境模拟扣分失败、权益发放失败 | 最终成功则扣分与权益匹配；最终失败则恢复积分或按明确补偿机制处理；处理中状态可追踪 |
| T08 / P0 | 未登录尝试兑换；A 尝试查看或操作 B 的兑换 | 身份要求符合规则；A 无法使用 B 的积分或读取、修改 B 的私有记录 |
| T09 / P1 | 兑换后刷新、重新登录，查看余额、记录和权益 | 结果保持一致；记录归属正确；若异步处理，在约定时限内收敛 |
| T10 / P1，条件 | 库存为 0 时兑换；库存为 1 时两人并发兑换 | 无库存不成功；最后一份最多发放一次；失败用户不损失积分 |
| T11 / P1，条件 | 限额剩余一次，连续或并发兑换；限额已用完再兑换 | 不突破限制；限制适用对象、周期和重置时点符合规则 |
| T12 / P1，条件 | 在过期、下架或规则变化前打开页面，变化后提交 | 提交时按约定规则校验；失效项不误兑换；费用变化后确认行为符合规则 |
| T13 / P1，条件 | 对兑换执行取消、退款，或模拟发放后的撤销 | 是否允许按规则判断；允许时积分和权益联动处理；重复操作不重复退分 |
| T14 / P2 | 查看兑换说明、取消确认、查看成功及失败提示 | 所需积分和权益说明清楚；提交前取消不扣分；提示与真实处理状态一致 |

### 5. 执行备注

- **执行顺序：**先完成 T01–T03，验证基本流程；再测重复、并发、故障和权限；最后补条件用例及体验检查。
- **集成检查：**若积分记账与权益交付由不同模块或服务完成，重点检查两侧结果、重试和补偿。具体依赖待确认。
- **证据：**记录兑换前后余额、时间、操作次数、系统实际提供的关联标识、兑换状态和权益结果；界面提示不足以证明账务正确。
- **环境限制：**并发和故障场景需要受控测试环境、测试账号及结果查询能力；缺少条件时标记“未验证”，不能记为通过。
- **暂不展开：**具体接口契约、管理员操作、性能容量和全面安全测试；目前信息不足，不能据此宣称完整覆盖。

### 6. 待确认问题

**必须补齐的信息：**

| 信息缺口 | 至少需要明确的内容 |
|---|---|
| 兑换对象与成功定义 | 兑换什么；何时算成功；用户在哪里取得权益 |

| 重复与并发 | 如何区分同一操作重试与新的兑换；积分或库存争抢如何裁决 |
| 测试与验收条件 | 测试版本、环境、账号、数据准备方式、结果查询能力、故障模拟条件及验收负责人 |
